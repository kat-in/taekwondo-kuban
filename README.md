# taekwondo-kuban

## Запуск

Нужны два процесса:

```bash
npm run dev
npm run dev:api
```

Frontend откроется на `http://localhost:5173`, API — на `http://localhost:5001`.

Проверка backend:

```bash
curl http://localhost:5001/api/health
```

Перед запуском backend должны быть установлены зависимости в `backend` и создан `backend/.env`. Не добавляйте `.env` и пароли в Git.

Переменные `backend/.env`:

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт API, по умолчанию `5001` |
| `ADMIN_PASSWORD` | **bcrypt-хэш** пароля админки, не сам пароль |
| `JWT_SECRET` | Секрет для подписи JWT |
| `NODE_ENV` | `production` включает строгий CORS и кэширование статики |
| `ALLOWED_ORIGINS` | Список origins через запятую; в `production` запросы с другими origin получают 403 |

Хэш пароля создаётся так:

```bash
cd backend
node -e "import('bcryptjs').then(b=>b.default.hash('ВАШ_ПАРОЛЬ',10).then(h=>console.log(h)))"
```

Менять пароль можно прямо в панели: `/admin/password`. Endpoint `POST /api/admin/password` проверяет текущий пароль и перезаписывает `ADMIN_PASSWORD` в `.env` (атомарно, через временный файл с правами `600`), поэтому перезапуск сервиса не нужен — новый хэш сразу применяется в памяти процесса. Если пароль задан вне `.env` (например, в `systemd` или `pm2`), endpoint вернёт 409 и попросит менять его в окружении сервера.

В токен входит отпечаток текущего хэша пароля, поэтому после смены пароля все ранее выданные токены перестают работать — включая тот, в котором пароль меняли. Фронтенд после успешной смены сам разлогинивает и просит войти с новым паролем. Токены, выпущенные до этой механики, перестают работать при первом же обращении к API.

Ограничения, которые действуют всегда: 8 неудачных попыток входа за 15 минут с одного IP, 40 изменений в минуту, 300 запросов в минуту на `/api`, 10 МБ на фото и 50 фото на альбом.

## Сборка

```bash
npm run lint
npm run build
```

Данные хранятся в `backend/data`, загруженные файлы — в `backend/uploads`. Для production настройте reverse proxy для `/api` и `/uploads` на порт backend.

Все ответы API возвращаются в едином формате: успех — данные (или `{ "success": true, "data": ... }` в админке), ошибка — `{ "success": false, "message": "..." }`.
